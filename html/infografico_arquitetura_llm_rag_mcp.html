Arquitetura de 3 Camadas para Aplicações de IA

Uma visão didática de como LLMs, RAG e MCP podem trabalhar em conjunto para produzir respostas mais inteligentes, contextualizadas, atualizadas e capazes de executar ações no mundo real.

Visão geral

As três camadas da arquitetura

Cada camada resolve um problema diferente. O LLM compreende e gera linguagem; o RAG fornece conhecimento externo; e o MCP conecta a IA a ferramentas capazes de consultar dados e executar ações.

1

LLM

Camada de Fundação

O Modelo de Linguagem Grande interpreta perguntas, identifica intenções, raciocina sobre o contexto recebido e produz respostas em linguagem natural.

🧠
Modelo de Linguagem Grande

Ex.: GPT, Claude, Gemini, Llama, Qwen e outros modelos locais ou em nuvem.

Como funciona?

  • Recebe uma instrução ou pergunta em linguagem natural.
  • Usa padrões aprendidos durante o treinamento para interpretar a intenção.
  • Gera texto, código, resumos, classificações ou explicações.
  • Pode cometer erros quando o conhecimento interno é insuficiente ou desatualizado.

Exemplo

Usuário: Explique o que é uma API.
LLM: Uma API é uma interface que permite a comunicação entre sistemas...
Valor entregue: compreensão de linguagem, raciocínio geral, geração de conteúdo e interação conversacional.
2

RAG

Camada de Conhecimento

O RAG — Retrieval-Augmented Generation — busca informações em fontes externas e fornece ao LLM um contexto relevante antes da geração da resposta.

🔎 📚
Recuperação + Contexto Aumentado

Fontes: documentos, páginas web, manuais, banco de dados, wiki corporativa e bases vetoriais.

Fluxo do RAG

  • A pergunta é transformada em uma consulta de busca.
  • O recuperador localiza trechos relevantes na base de conhecimento.
  • Os trechos recuperados são adicionados ao prompt.
  • O LLM responde usando o contexto fornecido.

Exemplo

Usuário: Qual é a regra de matrícula no curso?
RAG: Consulta o regulamento acadêmico e recupera os artigos relevantes.
LLM: Segundo o regulamento, a matrícula deve ser feita...
Valor entregue: respostas fundamentadas, atualizadas, específicas do domínio e com menor risco de alucinação.
3

MCP

Camada de Ação

O Model Context Protocol oferece um padrão para conectar aplicações de IA a ferramentas, APIs, arquivos, bancos de dados e serviços externos.

🔌 ⚙️
Host → Cliente MCP → Servidores MCP

Integrações com APIs, sistemas de arquivos, bancos de dados, agendas, e-mail e aplicações corporativas.

Como funciona?

  • O LLM identifica que uma ferramenta é necessária.
  • O cliente MCP descobre e chama a ferramenta adequada.
  • O servidor MCP executa a operação no sistema externo.
  • O resultado retorna ao modelo para validação e apresentação ao usuário.

Exemplo

Usuário: Gere o relatório mensal e salve no Drive.
MCP: Consulta a base, gera o arquivo e envia ao armazenamento.
LLM: Relatório gerado e salvo com sucesso.
Valor entregue: ações reais, automação de tarefas e integração padronizada com ferramentas externas.

Integração

Como as três camadas trabalham juntas

Em uma aplicação completa, as camadas atuam em sequência e podem ser acionadas de forma condicional, conforme o tipo de solicitação.

👤1. Solicitação
O usuário faz uma pergunta ou pede uma ação.
→
🧠2. Interpretação
O LLM identifica intenção e dados necessários.
→
🔎3. Recuperação
O RAG busca informações relevantes.
→
🔌4. Ação
O MCP chama ferramentas e serviços.
→
✅5. Resposta
O usuário recebe resultado e confirmação.

Casos práticos

Exemplos detalhados de uso

Os exemplos abaixo mostram quando cada camada é utilizada e como elas se combinam em cenários reais.

1. Assistente acadêmico

Responde dúvidas sobre matrícula, estágio, TCC e normas da instituição.

LLM RAG Documentos institucionais
Aluno: Quantas horas complementares preciso concluir?
Sistema: Recupera a resolução do curso e localiza a carga horária exigida.
Resposta: O regulamento estabelece 200 horas de atividades complementares.
Explicação: o LLM interpreta a pergunta; o RAG consulta o documento oficial; o MCP não é necessário, pois nenhuma ação externa precisa ser executada.

2. Relatório de vendas automatizado

Consulta dados de vendas, produz um resumo e salva o relatório em um serviço de arquivos.

LLM RAG MCP Banco de dados
Gestor: Gere um relatório das vendas do primeiro trimestre.
Sistema: Consulta o banco, calcula totais, identifica tendências e gera um PDF.
Resposta: Relatório criado e salvo. As vendas cresceram 12% no período.
Explicação: o MCP acessa o banco de dados e o armazenamento; o RAG fornece dados; o LLM transforma números em uma explicação executiva.

3. Suporte técnico corporativo

Ajuda funcionários a resolver erros de sistemas usando manuais internos e histórico de chamados.

LLM RAG Base de conhecimento
Usuário: O sistema apresenta o erro E-104 ao enviar uma nota.
Sistema: Busca ocorrências do erro, manual do ERP e soluções anteriores.
Resposta: O erro normalmente ocorre por ausência do código tributário...
Explicação: o RAG reduz respostas genéricas ao trazer soluções específicas da empresa. O MCP pode ser acrescentado para abrir automaticamente um chamado.

4. Assistente de agenda

Verifica horários livres, cria eventos e envia convites aos participantes.

LLM MCP Calendário E-mail
Usuário: Marque uma reunião de 30 minutos amanhã à tarde.
Sistema: Consulta a agenda, identifica um horário livre e cria o evento.
Resposta: Reunião agendada para amanhã, às 15h.
Explicação: o LLM interpreta uma solicitação ambígua; o MCP consulta e altera a agenda. O RAG só seria necessário se políticas ou regras adicionais precisassem ser consultadas.

5. Análise de contratos

Localiza cláusulas, resume obrigações e compara documentos com políticas internas.

LLM RAG Documentos jurídicos
Analista: Quais são as multas previstas neste contrato?
Sistema: Recupera as cláusulas de penalidade e suas referências.
Resposta: Foram identificadas três multas: atraso, descumprimento e rescisão...
Explicação: o LLM resume e organiza; o RAG mantém a resposta vinculada às cláusulas reais. A aplicação deve exibir fontes e páginas para auditoria.

6. Monitoramento de infraestrutura

Analisa métricas de serviços e executa ações controladas diante de incidentes.

LLM RAG MCP Observabilidade
Operador: Por que a API ficou lenta e o que devo fazer?
Sistema: Consulta métricas, logs, runbooks e incidentes anteriores.
Resposta: A latência aumentou após saturação do pool de conexões. Recomenda-se...
Explicação: o RAG recupera runbooks; o MCP consulta métricas e pode reiniciar um serviço, desde que existam permissões, validações e confirmação humana.

Decisão arquitetural

Comparação entre LLM, RAG e MCP

Aspecto LLM RAG MCP
Objetivo principal Compreender e gerar linguagem. Fornecer conhecimento externo. Executar ações e integrar ferramentas.
Entrada típica Prompt, histórico e contexto. Consulta semântica ou textual. Chamada estruturada de ferramenta.
Saída típica Texto, código ou decisão. Trechos, documentos e evidências. Resultado de API, arquivo ou operação.
Principal risco Alucinação ou interpretação incorreta. Recuperação irrelevante ou desatualizada. Ação indevida ou acesso excessivo.
Controle recomendado Prompt, validação e avaliação. Fontes, filtros, ranking e citações. Permissões, confirmação e auditoria.
Quando usar Conversação, análise, explicação e geração. Conhecimento privado, atualizado ou especializado. Quando a IA precisa consultar ou alterar sistemas.

Projeto e governança

Boas práticas para aplicações confiáveis

🎯

Precisão

Use fontes verificáveis, busca semântica, filtros por domínio e avaliação contínua das respostas.

🛡️

Segurança

Aplique autenticação, autorização mínima, isolamento de ferramentas e confirmação para ações críticas.

🧾

Rastreabilidade

Registre prompts, fontes consultadas, ferramentas utilizadas, parâmetros e resultados obtidos.

📈

Observabilidade

Monitore latência, custo, taxa de erro, qualidade da recuperação, uso de ferramentas e satisfação.

Exemplo de fluxo técnico simplificado

usuário → aplicação aplicação → LLM: interpretar intenção LLM → RAG: buscar contexto, quando necessário RAG → base de conhecimento: recuperar evidências LLM → MCP: selecionar ferramenta, quando necessário MCP → sistema externo: executar consulta ou ação sistema externo → MCP → LLM: devolver resultado LLM → aplicação → usuário: gerar resposta final

Perguntas frequentes

É obrigatório usar as três camadas?

Não. Uma aplicação simples pode usar apenas um LLM. O RAG e o MCP devem ser adicionados quando houver necessidade de conhecimento externo ou ações em sistemas.

RAG é o mesmo que memória?

Não exatamente. RAG recupera informações de uma base externa. Memória normalmente representa dados persistentes sobre conversas, preferências ou eventos anteriores.

MCP substitui APIs?

Não. O MCP organiza e padroniza como aplicações de IA descobrem e usam ferramentas. As APIs continuam sendo parte das integrações.

Como reduzir riscos em ações automáticas?

Use permissões mínimas, listas de ferramentas autorizadas, validação de parâmetros, confirmação humana e registros de auditoria.
