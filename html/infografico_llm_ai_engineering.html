Como um LLM transforma texto em resposta

Um LLM não “entende” como uma pessoa. Ele calcula probabilidades para prever o próximo token com base no contexto, nos padrões aprendidos durante o treinamento e nos parâmetros configurados na inferência.

💬
1. Entrada

O usuário envia uma pergunta, instrução, texto ou documentos.

Explique RAG com um exemplo simples.
🔤
2. Tokenização

O texto é quebrado em unidades menores chamadas tokens.

"inteligência" → ["int", "elig", "ência"]
🧠
3. Transformer

Camadas de atenção calculam quais partes do contexto são mais relevantes.

Atenção: pergunta ↔ contexto ↔ histórico
✨
4. Próximo token

O modelo gera tokens um a um até formar a resposta final.

Glossário aplicado

Conceitos, técnicas e exemplos

🔤

Tokens

Unidades de texto processadas pelo modelo. Podem representar palavras, partes de palavras, pontuação ou espaços.

Exemplo:

Um prompt longo com muitos documentos consome mais tokens, aumenta custo e pode elevar a latência.

🎯

Atenção

Mecanismo que ajuda o modelo a ponderar partes relevantes do contexto ao gerar cada token.

Exemplo:

Ao responder sobre “Maria”, o modelo pode dar mais peso às frases que mencionam Maria do que a outras partes do prompt.

🌡️

Temperatura

Controla a aleatoriedade da geração. Valores baixos favorecem respostas previsíveis; valores altos geram variedade.

Exemplo:

temperature=0.2 para respostas técnicas; temperature=0.8 para brainstorming.

🎲

Top-K e Top-P

Limitam o conjunto de tokens candidatos para tornar a resposta mais controlada.

Exemplo:

top_p=0.9 usa apenas tokens cuja probabilidade acumulada alcance 90%.

🪟

Janela de contexto

Quantidade máxima de tokens que o modelo consegue considerar de uma vez.

Exemplo:

Em RAG, documentos precisam ser divididos em chunks para caber dentro da janela de contexto.

⚡

Inferência

Processo de executar o modelo para gerar uma resposta a partir do prompt.

Exemplo:

Servir um modelo com vLLM ou Ollama e expor uma API compatível com OpenAI.

⚠️

Alucinação

Quando o modelo gera informação plausível, mas incorreta, sem base confiável no contexto.

Mitigação:

RAG, checagem de fontes, resposta “não sei”, validação por regras e guardrails.

📚

RAG

Retrieval-Augmented Generation: busca informações em uma base externa e injeta trechos relevantes no prompt.

Exemplo:

Chatbot que responde perguntas sobre normas da UFPI usando PDFs indexados em ChromaDB.

🧬

Embeddings

Representações vetoriais que capturam similaridade semântica entre textos.

Exemplo:

Transformar perguntas e parágrafos em vetores para fazer busca semântica em um banco vetorial.

⚙️

Parâmetros do modelo

Pesos aprendidos durante o treinamento. Armazenam padrões estatísticos da linguagem e do conhecimento visto nos dados.

Exemplo:

Um modelo 7B tem cerca de 7 bilhões de parâmetros.

🤖

Agentes

Aplicações que usam LLMs para planejar ações, chamar ferramentas e executar tarefas em etapas.

Exemplo:

Agente que recebe uma solicitação, consulta uma API, gera relatório e salva um arquivo.

📈

Observabilidade

Monitoramento de latência, tokens, custo, erros, qualidade e segurança das respostas.

Exemplo:

Prometheus coleta métricas; Grafana mostra dashboards; LangSmith rastreia prompts e cadeias.

@RestController
class ChatController {
  private final ChatClient chatClient;

  ChatController(ChatClient.Builder builder) {
    this.chatClient = builder.build();
  }

  @GetMapping("/chat")
  String chat(@RequestParam String pergunta) {
    return chatClient.prompt()
      .user(pergunta)
      .call()
      .content();
  }
}

from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:11434/v1",
    api_key="ollama"
)

resp = client.chat.completions.create(
    model="llama3.2:3b",
    messages=[
        {"role": "system", "content": "Responda em português, com objetividade."},
        {"role": "user", "content": "Explique RAG em 3 tópicos."}
    ],
    temperature=0.2
)

print(resp.choices[0].message.content)

Ideias práticas com exemplos

Fluxo: carregar PDFs → quebrar em chunks → gerar embeddings → salvar em banco vetorial → recuperar trechos relevantes → montar prompt → gerar resposta com fontes.

from langchain_text_splitters import RecursiveCharacterTextSplitter
from langchain_chroma import Chroma
from langchain_ollama import OllamaEmbeddings, ChatOllama

textos = ["Regulamento: o aluno deve cumprir a carga horária..."]
splitter = RecursiveCharacterTextSplitter(chunk_size=800, chunk_overlap=120)
docs = splitter.create_documents(textos)

emb = OllamaEmbeddings(model="nomic-embed-text")
db = Chroma.from_documents(docs, embedding=emb, persist_directory="./chroma")

pergunta = "Qual regra vale para carga horária?"
contexto = "\n".join([d.page_content for d in db.similarity_search(pergunta, k=3)])

llm = ChatOllama(model="llama3.2:3b", temperature=0.2)
resposta = llm.invoke(f"Responda usando apenas o contexto:\n{contexto}\n\nPergunta: {pergunta}")
print(resposta.content)

Uma API permite integrar o LLM com frontend web, aplicativos, sistemas corporativos e serviços externos.

from fastapi import FastAPI
from pydantic import BaseModel
from openai import OpenAI

app = FastAPI(title="API de IA Generativa")
client = OpenAI(base_url="http://localhost:11434/v1", api_key="ollama")

class ChatRequest(BaseModel):
    pergunta: str

@app.post("/chat")
def chat(req: ChatRequest):
    resp = client.chat.completions.create(
        model="llama3.2:3b",
        messages=[{"role":"user", "content": req.pergunta}],
        temperature=0.3
    )
    return {"resposta": resp.choices[0].message.content}

def montar_prompt(pergunta: str, contexto: str) -> str:
    return f"""

Se o contexto não for suficiente, responda: "Não encontrei informação suficiente.".

CONTEXTO:
{contexto}

PERGUNTA:
{pergunta}
"""

# Estratégia adicional: bloquear perguntas fora do domínio
PALAVRAS_DOMINIO = ["regulamento", "disciplina", "matrícula", "projeto"]

def pergunta_no_dominio(pergunta: str) -> bool:
    p = pergunta.lower()
    return any(t in p for t in PALAVRAS_DOMINIO)

Boas práticas para sistemas confiáveis de IA

1. Defina o caso de uso e o domínio

Evite “usar LLM para tudo”. Comece com uma tarefa clara: responder dúvidas, classificar documentos, resumir relatórios ou gerar rascunhos.

2. Escolha a estratégia: prompt, RAG, fine-tuning ou agente

Prompt engineering resolve casos simples. RAG é indicado quando a resposta depende de documentos atualizados. Fine-tuning é útil para estilo, formato e padrões recorrentes. Agentes servem para workflows com ferramentas.

3. Avalie qualidade com exemplos reais

Crie um conjunto de perguntas/respostas esperadas e avalie precisão, completude, aderência às fontes e segurança.

4. Monitore custo, latência e falhas

Prompts grandes, modelos maiores e contexto extenso aumentam custo e tempo de resposta.

5. Proteja dados e controle permissões

Use autenticação, controle de acesso, mascaramento de dados sensíveis, logs seguros e revisão humana quando necessário.
